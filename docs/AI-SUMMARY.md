# AI-SUMMARY

## Project: MetaList
- Single-user FastAPI app for hierarchical notes with SSR + a diff-based `POST /api2/notes/view`.

## Architecture
- Entry: installed CLI `metalist` → `main.py:main()`; both plain `metalist` and source-checkout `python main.py` bootstrap every known namespace and exit after printing the per-namespace URLs. Explicit namespace/port arguments are forwarded by the installed console wrapper into the same parser.
- Packaging: `app/version.py` is the single `0.3.14` version source consumed dynamically by `pyproject.toml` and runtime config; the package includes templates/static assets, and installed helper commands include `metalist-audit-encryption`, `convert-from-legacy.py`, and `generate-lan-cert.sh`.
- Release workflow: `.github/workflows/publish-pypi.yml` builds the package and publishes it to PyPI via GitHub Trusted Publishing on `v*` tags or manual dispatch.
- Self-update: `metalist update` dispatches before normal startup through `app/services/self_update.py`; it first validates the latest PyPI release metadata and compares it with `app/version.py`. A current or newer installation reports its version without resolving uv or stopping namespaces. An available update is pinned to the exact PyPI version, then the updater resolves uv plus an external updater before stopping anything, stops listener processes on every saved namespace port, waits for the invoking CLI process to release the tool environment, runs a forced cache-refreshed uv install, relaunches plain `metalist`, and reports the installed target version. Windows uses a separate PowerShell console; macOS/Linux use detached `/bin/sh` while exposing the same command to users.
- Prelaunch gate: `main.py` resolves `METALIST_ENVIRONMENT` from the process environment or the ignored repository-root `.env`, prints `development`/`production`, and runs Python + JS startup sanity checks once in the parent process only in development. Missing configuration means production. Python rules live in `app/startup_sanity.py`; JS rules live in `app/startup_js_sanity.py` and forbid native browser `alert`/`confirm`/`prompt` dialogs so user communication stays in MetaList UI; shared constants live in `app/startup_sanity_config.py`.
- Startup bootstrap: the installed `metalist` command creates `~/MetaList/namespaces/default/default.metalist.db`, its default settings row, and suggested launch profile only when no namespaces exist. A deleted `default` stays deleted while another namespace exists; deleting the final namespace recreates a fresh `default` on the vacated ports. `main.py` resolves `--namespace`, positional namespace shorthand (`metalist cla` or `python main.py cla`), `--port`, `--https-port`, and the non-persistent `--enable-shell` capability before importing `app.main`, so explicit single-namespace launches still expose the right DB path and listener ports at import time. All-namespace launches propagate `--enable-shell` to every child, force the default host to loopback, and print a conspicuous top-level enablement banner.
- Namespace launch profiles: `app/server_runtime.py` stores remembered per-namespace HTTP / HTTPS ports as plaintext metadata in each namespace's main `*.metalist.db`; the old global `~/MetaList/namespaces.db` registry is ignored. Schema-v1 `mcp_port` values remain inert compatibility metadata only.
- AI/agent boundary: Authenticated chat uses an application-owned read-only investigation loop plus explicitly requested bulk tag proposal operations. Every request carries required visible-tab and originating-scope-tab IDs; the server verifies the visible tab, then filters canonical search/sort matches through the provider disclosure boundary before freezing immutable `S0`. `@password` always removes its complete subtree. OpenAI/future cloud providers additionally share one namespace policy with OR whitelists, OR blacklists (blacklist wins), case-insensitive literal phrases, and canonical effective-tag matching including inheritance plus ontology implications/synonyms; Ollama ignores those configurable lists. Hidden ancestors always hide descendants. Filtering precedes counts, evidence, citations, debug, and provider prompts. Hovering chat calls the same server evaluator and marks hidden notes with readable gray backgrounds. A temporary Reference source is navigation, not a new evidence scope, so follow-ups retain the search that produced the answer even while the reference remains open. A later AI-reference click replaces that active temporary query, while ordinary note-internal reference following still stacks. Route selection receives a trailing content-free `ROUTE_SELECTION_REQUEST` with the exact current request, user-driven query, scope metadata, and note/root counts; explicit saved-note requests cannot validate as `respond`, while corrections/challenges default to direct conversation unless they explicitly request fresh note evidence. Instructor routes `respond` vs. `investigate_current_scope`. Investigation lazily walks complete roots in canonical order, retains the longest leading prefix within one provider-specific evidence-token limit, and sends exactly one compact recursively nested payload directly to final generation. Roots never split; retained note content is complete; later roots are omitted and exact included/omitted counts prevent exhaustive claims. There is no multipage loop, working summary, facet browser, tag narrowing, ranked-source memory, or source-rehydration pass. Ollama defaults to 5,000 evidence tokens (range 500–24,000); OpenAI defaults to 250,000 (range 500–500,000). Final prose is capped at 1,024 tokens for Ollama and 8,192 for OpenAI; a provider-reported length stop fails visibly. OpenAI uses `store: false`; protected namespaces persist its key encrypted while plaintext namespaces hold it only in server session memory. Scope/actions/evidence/traces are session-only and never canonical history. Full contract: `docs/design/agent-harness.md`.
- Namespace switching/launching: `app/services/namespace_switcher.py` lists known namespaces, suggests ports that avoid both saved namespace reservations and active OS listeners, and automatically repairs duplicate saved profiles during all-namespace startup (default first, then alphabetical), persisting the reassigned ports and printing a concise before/after warning. It reuses an already-running target with a warm cache when its saved launch profile is unchanged, restarts it when requested ports changed, relaunches the recorded entrypoint (installed CLI or source script), rejects launch-time listener races without terminating the port owner, and writes child logs under `~/MetaList/logs/`. `app/services/namespace_runtime_guard.py` revalidates each non-test process's namespace DB/profile identity every five seconds and self-terminates if that identity disappears. Windows listener discovery and process termination use built-in PowerShell through `app/services/windows_process_control.py`; macOS/Linux retain the POSIX `lsof` and signal path. Plain all-namespace orchestration deliberately restarts namespaces to pick up current code.
- Child entrypoint: `serve_namespace.py` is the namespace-serving source entrypoint; installed child launches carry `METALIST_ORCHESTRATED_CHILD=1`. Both paths bypass parent-only sanity checks and the already-completed all-namespace encryption audit, preventing false readiness timeouts on large Windows vaults. The parent tracks the child process and includes the child log tail if it exits or misses the readiness deadline.
- `app/main.py`: FastAPI wiring, middleware, startup bootstrapping, SSR templates. Static assets and Mako templates are served directly from `app/static/` and `app/templates/`; Python auto-reload remains disabled, so rerun `main.py` to load Python changes.
- `app/static/js/main.js`: Browser bootstrap; awaits `Auth.init()`, `ModeManager.init()`, and `CommandPalette.init()` before revealing the app, and sets `document.body.dataset.appReady` for deterministic Cypress startup waits.
- Startup intro gate: `app/templates/index.html` + `app/static/js/modules/auth.js` can show a login/startup MP4 before revealing login or the app; the login card now shows a single namespace-aware title (`MetaList` for `default`, `MetaList [work]` otherwise) plus a bottom namespace picker that can redirect before authentication; this is controlled by `STARTUP_ANIMATION_ENABLED` and defaults off.
- `app/api/routes`: JSON routers mounted under `API_PREFIX` (default `/api2`).
  - `app/api/routes/notes.py`
  - `app/api/routes/auth.py`
  - `app/api/routes/files.py`
- `app/api/middleware/auth.py`: Auth middleware gating routes when a password exists.
- `app/usecases`: Cmd* application commands (transport-agnostic orchestration).
- Collapse controls distinguish root-only current-context actions from recursive current-context actions; a note's context menu can recursively expand or collapse only that note and its descendants. Recursive target discovery happens on the server so hidden descendants need not be rendered.
- `app/services`: Auth, tokens, cache, sync, undo, integrity, note store, file storage, snapshots, tab state cache, session-timeout settings.
- `app/services/client_state_service.py`: Stores namespace-scoped command-palette preferences/usage in `app_settings`; payloads are DEK-encrypted when the namespace is password-protected and rewrite with password creation/removal.
- `app/services/ai_chat.py` + `app/services/agent/` + `app/services/ollama_provider.py`: Session-token-hash canonical chat plus the scoped runtime. `scope.py` freezes canonical view membership/content and structural ancestor paths; every Send's newly captured scope is authoritative over stale conversation claims, while conversation-aware routing resolves elliptical retries of unresolved note tasks. `investigation.py` lazily retains one ordered complete-root prefix under the provider evidence-token limit; `evidence_serialization.py` emits full compact nested trees; `context.py` builds one direct final request. Evidence exposes each note's direct `proposed_tags` separately from accepted `tags`; inherited/implied tags are not sent. Every tag-generation request requires the remembered three-way existing/new/both chooser; request wording and model interpretation cannot bypass it. Each batch also receives the exact request as a binding semantic topic filter, using examples to disambiguate the intended subject and excluding broad neighboring classifications. Generation randomizes whole roots before token batching and may make three cumulative correction attempts for avoidable validation failures; new-only collisions with undisclosed namespace vocabulary are silently removed. Generation alone creates the locked progress/cancellation card; programmatic proposal acceptance/removal uses the ordinary busy/thinking state and performs its atomic update without an intermediate cancelable panel. The versioned `scoped_investigation_v7` skill supersedes all paging/summary skill contracts. `InferenceAdapter` selects Ollama or OpenAI without LiteLLM; Instructor owns route retries and the provider owns final streaming. `openai_cost_tracking.py` aggregates API-reported ordinary input, cached input, cache writes, and output in process memory only.
- Agent diagnostics/debug: eye mode defaults hidden and persists; hidden mode uses one stable animated `Working…` row, then preserves a calm `Only using X of Y root notes for answer` notice before the answer when trailing roots were omitted. Eye-mode panels update in place for scope freeze, structured attempts/retries, action/reason, ordered-root retention, the one evidence payload, and final writing, with approximate input/output tokens and per-step duration. Initial structured attempts omit `attempt 1 of 2`; only a real retry displays `attempt 2 of 2`. Stop/Clear cancel provider work. Latest-run Agent Debug retains exact wire bodies/responses, frozen scope, retained/omitted roots, the full evidence payload, timing/errors, and final output in session memory only; Copy all emits formatted JSON. Final evidence uses validated `[[UUID]]` citations rendered as numbered superscripts. The visible References section is root-deduplicated, while hidden UUID/OR navigation preserves exact cited child paths and gray-redacts unrelated siblings.
- `app/services/note_store.py`: Canonical in-memory store for decrypted notes + accepted/proposed tag sources + parent/prev/next links. Proposed non-meta tags inherit like accepted tags and join them only at the effective search layer; ontology inference runs over that combined set. Hydration reuses the cache's already-sanitized HTML and extracted plain text instead of parsing every note twice.
- `app/services/runtime_lock.py`: Fail-closed encrypted-namespace lock teardown; explicit logout removes the live DEK reference and purges plaintext-bearing runtime stores, but Python/browser allocation release is not guaranteed forensic memory erasure. Idle expiry only invalidates browser authentication so re-login can reuse the warm hydrated cache. Process/browser memory inspection while unlocked remains outside the application threat boundary.
- `app/services/file_storage.py`: Stores file attachments in a sibling `*.files.db` SQLite database; uses plaintext rows when the app has no password and encrypted metadata/blob rows when the app is in encrypted mode.
- `app/services/sound_storage.py`: Memory-first reusable sound asset store backed by a separate `sounds` table in the sibling `*.files.db`; includes non-deletable `builtin.default_chime`, encrypted metadata/blob persistence when password-protected, 2 MB / 10 second per-sound caps, and a 50 MB uploaded-library cap.
- `app/services/search_history.py`: Memory-first tag-activity store persisted as one namespace DB row. Intentional note edit/expand/full-screen/command engagements plus successful reorder/indent/outdent mutations credit raw explicit/inherited tags. A default-on persisted preference limits each note to one credit per active tab/executed-search context using a complete credited-note set; the context never filters which note tags receive credit, and disabling the preference counts every qualifying interaction. Structural no-ops are neutral, and leaving then re-entering a context starts a new flow. A successful explicit-tag addition separately credits only each newly added case-insensitive tag. Accepting a search suggestion credits that selected known tag without flow deduplication; clicking a search-context tab credits its known positive tag terms while ignoring exclusions and quoted text. Searches themselves, programmatic tab switches, removals, and case-only tag changes are neutral. Sparse daily buckets retain the latest 365 populated days. An ordered configurable window list (default 1/7/30 days) controls personalized suggestion slots; one command-palette modal combines the window editor, default-on per-context note-credit and suggestion-label preferences, daily tag-credit statistics, and confirmed reset. The aggregate payload encrypts at rest when the namespace is password-protected.
- `app/services/file_registry.py`: In-memory registry of valid file UUIDs plus attachment thumbnail kinds; startup/login bootstraps this metadata without hydrating file blobs.
- `app/services/backup_settings_service.py`: Stores the configured backup folder, selected namespaces, and retention count in the namespace DB; when namespace encryption is enabled, that payload is encrypted at rest too. The backup settings route derives its displayed namespace catalog strictly from namespace folders containing their expected main database, filters deleted names out of saved selections, and skips stale deleted selections when running a backup as long as another selected namespace still exists.
- Notes schema: `notes.content`, accepted `notes.tags`, and unresolved `notes.proposed_tags` are persisted; both tag sources are space-separated strings with separate encryption metadata. Proposed tags affect inheritance, ontology-aware search/autocomplete, and Untagged Notes immediately, but do not activate formatting or tag commands until accepted. `notes.updated_at` means note body content changed; tag/proposal-only edits, structural relinks, collapse state, encryption rewrites, and no-op saves preserve it. The search index dynamically infers `@image` from inline image markup, Markdown image links, or image file refs without writing it into `notes.tags`; hydration uses compiled detection and skips reference parsing entirely when `[[` is absent.
- `app/services/snapshot.py`: Builds the view snapshot used by `/api2/notes/view`.
- `app/services/footnote_rendering.py`: Scoped-only `@footnote` moves marked spans into a per-note always-visible References section; identical text/targets share numbers, Markdown links and rich HTML remain rendered, URL-only link labels reuse background title fetching and cached title/domain display, and local superscript buttons scroll to the reference. Collapsed footnote notes format before CSS clamping so later standalone scopes keep their first-line markers; a marker click expands the note before navigating. `footnote_layout.py` attaches footnote-only lines/paragraphs to preceding prose and preserves a single paragraph gap; edit content and layout remain raw. Add Style requires a selection and reuses dedicated footnote scopes.
- `app/services/content_formatting.py`: Applies view-only meta-tag formatting (including scoped `@monospace`, colors, and fluorescent `@highlighter`) with optional wrapper scoping, auto-links bare `http(s)` URLs in rendered notes, renders cached standalone URL titles when available, normalizes rendered anchors to open in a new tab, and lets `@markdown` auto-render paired LaTeX delimiters as MathML without interfering with explicit scoped `@LaTeX` wrappers. Markdown `mermaid` fences are server-marked and browser-rendered as responsive SVG by a strict-mode, locally vendored runtime that lazy-loads only when needed.
- `app/services/link_titles.py`: Memory-first cache + bounded background fetcher for compact standalone URL titles. Text fields (`url`, `title`) persist encrypted-at-rest in the main DB `link_titles` table when namespace encryption is enabled; runtime rendering only reads the in-memory cache. Every initial URL/redirect resolves fail-closed to globally routable addresses, and the direct HTTP transport pins the socket to that validated IP while retaining the original hostname for Host/TLS verification, preventing DNS-rebinding SSRF. Early failed/no-title lookups retry on short adaptive backoff before settling into longer refresh intervals.
- `app/services/reminders.py`: Namespace-local in-memory reminder store + deterministic scheduler for privacy-first in-app scheduled prompts. Reminder payload rows live in `reminders`, load at startup/login, and encrypt the full JSON payload at rest when namespace encryption is enabled; browser/system push is intentionally not modeled. Server owns reminder truth; the browser keeps a refreshed in-memory mirror only for local surfacing.
- `app/services/tag_term_matching.py`: Shared helper for connector-aware, punctuation-tolerant tag suggestion matching/ranking (`-`, `_`, `.`, `/`) used by search suggestions and tag suggestions.
- `app/services/embedded_references.py`: Resolves note/file UUID references in view mode (embedded notes, note previews, file cards, missing/cycle markers).
- `app/services/tab_state.py`: Stores namespace-scoped tab workspace state (`activeTabId`, `tabOrder`, and per-tab search/scroll/sort metadata) in the main SQLite DB; rows stay plaintext without a password and are DEK-encrypted at rest when the namespace is password-protected.
- `app/services/login_rate_limit.py`: In-memory login attempt throttling for `/api2/auth/login`.
- `app/services/runtime_hardening.py`: Startup hardening (disable core dumps; macOS swap/hibernation enforcement).
- `app/services/diagnostics.py`: Privacy-bounded runtime diagnostics for persistent namespace server logs, fatal fault logs, unhandled process/thread/asyncio exception types/frames, slow in-flight requests, event-loop stalls, on-demand thread dumps via `SIGUSR1`, bounded recycling for direct append logs, and fail-fast startup log disk bounds. Locked startup diagnostics are plaintext but cannot hydrate encrypted vault data; successful login switches file records plus direct stdout/stderr to per-record DEK-authenticated `MLLOG1` envelopes before decrypted stores load, disables plaintext fault output until logout, and restores plaintext startup diagnostics only after runtime purge. Request bodies/query values and exception messages are not persisted; password request fields are `SecretStr`; raw Uvicorn access logs are disabled.
- `app/static/js/modules/mode-manager/services/html-paste-sanitizer-service.js`: Client-side sanitizer for external HTML paste in edit mode (URL/style allowlist + blocked tags + image guardrails).
- `app/static/note-html-policy.json`: Shared stored-note HTML allowlist. Vendored DOMPurify applies it before browser save/split requests; `app/security/note_html.py` independently applies it with nh3 before DB writes and when decrypted legacy content enters the renderable cache.
- `app/security/encryption.py`: Crypto facade (AES-GCM, Argon2id, versioned vault metadata + key mgmt helpers).
- `app/encryption_audit.py`: Read-only, fail-closed audit of every encrypted namespace's main/files SQLite payload contract; exposed as `scripts/audit_encrypted_namespaces.py` and installed command `metalist-audit-encryption`. Startup permits only explicitly classified version-0 client-state plaintext needed by the authenticated `0→1` migration; every other finding raises before listeners launch. The standalone command exits nonzero for both migration and fatal findings so backup gates require fully encrypted storage.
- `app/db`: `session.py` (begin_writer/connect_reader/read guard), `schema.py`, `notes_sql.py`, `settings_sql.py`.
- `app/static` & `app/templates`: Frontend assets and Mako templates.
- `tests/unit`: targeted pytest coverage plus Node `.mjs` unit tests for shared frontend logic; there is no current Cypress harness.

## Design
- Modal dismissal: `BaseModal` injects a standard upper-right circular `×` after every full-content render; `×`, `Escape`, and outside click share the same close request path. Dismiss-only `Close`/`OK` footer buttons are not used, while workflow `Cancel`/`Back` actions remain.
- Pattern: usecases (Cmd*) orchestrate services; services encapsulate DB work + undo logging.
- State: Notes stored as parent/prev/next pointers; decrypted cache is preloaded; sync UUIDs/locks managed in `app/services/sync.py`; active tabs/search/scroll are snapshotted via `tab_state_store` into the namespace DB so reopening the app or restarting the server restores the last view; command-palette prefs/usage are persisted per namespace in `app_settings` instead of browser `localStorage`. `Note Layout & Appearance…` uses those prefs for root-note size (default `Larger`), child indentation, and vertical spacing; visible list tags wrap within 25% of the note row. Every note context menu ends with a non-interactive dark footer showing locally formatted `Created` and `Updated` timestamps; the former hover-popup preference is obsolete.
- Root sort modes: per-tab server-owned `sortMode` (`normal`, `created`, `updated`, `alphabetical`, `content-volume`) lives in `app/services/tab_state.py`; datetime modes sort/window roots by the newest matching timestamp anywhere in each root subtree, alphabetical mode sorts by root content, and content-volume mode sorts largest-first by summed HTML-stripped character counts across each entire root subtree. Equal volume totals preserve canonical root order. The client renders day separators from `snapshot.rootSortBuckets` only for datetime modes.
- Untagged view: transient client-owned `isUntaggedView` is a tab-agnostic display override selected through `View: Untagged notes`/`View: All notes` and shown as a dismissible pill. It preserves the underlying tab/search and matches notes with no non-meta effective tags, so inherited and ontology-inferred classifications exclude a note while `@` formatting/meta tags do not. Clicking any tab or changing search dismisses it.
- Bulk expand/collapse: command-palette Expand All and Collapse All update only root notes in the active search context; descendant collapse states are preserved.
- Per-note collapse affordances: the server marks notes with children as collapsible; the browser also promotes rendered content that occupies multiple visual lines. Inline fragment rectangles that overlap on one visual line are grouped together, preventing mixed-size title/domain link markup from creating a false collapse arrow.
- Mutation safety: mutating FastAPI routes are expected to carry `@transactional_route`; startup sanity enforces the decorator ordering in source, and request-scoped write sessions commit once at the end of the wrapped request path.
- Diff caching: Server caches each `(client, tab, search)` view and the client keeps per-tab note-hash maps so `/notes/view` diff payloads stay scoped to the active tab.
- Tab switch perf: Client can detach/cache the `#notes-container` subtree per tab and restore it instantly on return, then call `/notes/view` to reconcile small diffs.
- Client busy model: `CommandGate.run(name, asyncFn)` is the single boundary for user-initiated server calls; it is the only code allowed to flip `ModeContext.isLoading`.
- Undo boundaries: client includes an `epoch` in `undoContext` (`tab/search/epoch`); global actions bump the epoch so undo/redo cannot cross those boundaries. Selection/deselection is not recorded: application undo/redo traverses saved mutations only. While editing, undo and `Cmd/Ctrl+Shift+Z` redo remain browser-native; `Cmd/Ctrl+Y` is mapped client-side to the active editor's local redo command. Sort-mode changes are global boundaries and blank undo/redo for the active tab context. Search input changes dismiss transient views and reset sort to Normal before execution.
- Error handling: fail-fast (internal errors crash; DB rollback triggers immediate process exit; request-validation crash toggle). Browser HTTP `4xx`/`5xx` responses report request/server failures without marking the client disconnected; only transport failures disable editing and enter the persistent soft-amber reconnecting state. Expected transport rejections bypass the fatal red stack overlay, while unexpected client exceptions still surface there.
- Auth: Argon2id password verifier protecting the DEK; encrypted settings require `vault_version` + full KDF profile (`kdf_algorithm`, `kdf_memory_cost_kib`, `kdf_parallelism`); new/changed passwords require 12-72 characters and offline zxcvbn score >=3 while existing passwords remain valid; `/api2/auth/login` is rate-limited; public routes use an exact-path allowlist (prefixes only for static files and opaque job polling), and production does not mount `/dev` DB-switching routes; pre-login namespace selection uses `GET /api2/auth/login-namespaces` + `POST /api2/auth/login-namespaces/open` without widening the authenticated namespace APIs; tokens are kept in-memory on the namespace server and default to no idle expiry, while the browser carries them in namespace-scoped HttpOnly `metalist_auth_<namespace>` cookies instead of `localStorage`; token issuance enforces one active session per namespace while allowing different namespaces to remain open together. Browser API/state debug output is disabled by default and shared loggers discard caller-provided payload/state values.
- Password generator: browser-only CSPRNG using `crypto.getRandomValues()` with rejection sampling; the generator lazy-loads the vendored official zxcvbn JavaScript build and displays its 0-4 score without sending generated passwords to a scoring endpoint.
- Shell security: `CmdRunShellStart` and `CmdRunShellStatus` reject execution/output access unless `--enable-shell` was supplied and password protection is enabled for the active namespace. HTTP routes require both a loopback client and loopback request host, allowing normal LAN note access on a wildcard bind without exposing shell; start rejects before loading the note or reaching the host-process service.
- Browser content security: every response receives a nonce-based CSP that permits scripts only from MetaList itself or the per-response nonce, restricts browser fetch/XHR/WebSocket connections to same-origin plus local `data:`/`blob:` resources, blocks objects/frames/base-tag replacement, and adds `nosniff`, deny-framing, no-referrer, restrictive permissions, and `Cache-Control: no-store, private` headers. Inline startup scripts carry the generated nonce; inline styles remain enabled for the current editor/rendering contract.
- Request boundary: listeners default to `127.0.0.1`; requests accept only loopback, the specific bind address, or `METALIST_ALLOWED_HOSTS`. Unsafe browser requests require an exact same-origin `Origin`; cookie-less bearer clients may omit it. `X-Forwarded-Host` is ignored, while Uvicorn trusts forwarded scheme/client metadata only from `METALIST_FORWARDED_ALLOW_IPS`.

## Workflows
- View/diff: `POST /api2/notes/view` → `app/services/snapshot.build_view_state()` → cold cache returns `snapshot.structure`, warm cache returns `snapshot.diffOps`, both with sparse `notes` + locks. Snapshot hierarchy/metadata share request-local traversal caches; identical structures skip branch diffing, and client no-op/lock-only diffs skip media scans.
- Root sorting: `POST /api2/notes/tab-state/sort-mode` updates per-tab sort state; subsequent `POST /api2/notes/view` responses echo `sortMode` and `rootSortBuckets`, and the client inserts ephemeral date separators between visible roots for datetime modes.
- Embedded references: view payload `notes[*].content` can include rendered `![[UUID]]` blocks (view mode only). Expanded hosts render the referenced root and its complete descendant subtree regardless of source collapse states, with no inner collapse controls and an arrow-only ↗ source link at the top-left; collapsed hosts reduce note embeds to compact source links retaining first-line footnote superscripts. Source links and reference context-menu `Go to Source` open a temporary duplicated tab whose UUID query is hidden behind a dismissible `Reference source` indicator; dismissing it returns to the originating context, preserves that tab's root/infinite-scroll tracking, and closes the temporary tab, while typing a search converts it into a normal search tab. Sole note references use the entire host background without an inner panel. `reference_presentation.py` scans incoming references once per snapshot and adds a ↖ source button opening a deduplicated namespace-wide `Referenced by` temporary view; ×/Escape return to the previous context. Reference mode is registered before tab activation so internal UUID queries never flash in the search field. View-indicator transitions skip note animations; scroll restoration preserves exact top position and discards pending restores after view resets. Host note hashes include rendered embed output and source-arrow presence.
- File attachments: `POST /api2/files/upload` stores the uploaded file in `*.files.db`, returns a UUID token, and the client inserts `![[UUID]]` into the active note (or a newly created note when none is active).
- Sound assets: `GET/POST/PUT/DELETE /api2/sounds` manages reusable uploaded sounds; `GET /api2/sounds/{id}/play` streams authenticated audio from the in-memory `sound_store`. The command palette exposes `Manage sounds…`; the reminder modal stores namespace default sound prefs plus per-reminder popup/`Got it` overrides, including explicit `Silent`.
- File downloads: rendered file references in view mode call `GET /api2/files/{file_id}/download`; metadata/blob rows are decrypted on demand rather than at startup.
- File trimming: `POST /api2/files/trim-unused` deletes attachment rows no longer referenced by any note; removing refs does not auto-delete files so undo/redo remains safe until trim runs.
- Tag persistence: tags are included in `snapshot.notes[*].tags` and are saved alongside note content on `PUT /api2/notes/{id}/save`; inferred search-only tags like `@image` are computed for the search index and are not shown in the tag bar. Tag-bar mouse/keyboard focus gets a persistent soft ring plus one subtle halo when Animated Transitions is enabled; reduced-motion and disabled-animation states keep only the static cue.
  - Selecting up to 25 characters in a note exposes **Add as Tag** in its context menu. `POST /api2/notes/{id}/add-selected-text-tag` reuses the most frequent explicit namespace tag across case and space/`-`/`_`/`.`/`/` joiner variants, or creates a sanitized case-preserving dash-joined tag, then applies it only to that note.
  - Right-clicking the actively edited note exposes an **Add Style** flyout. Whole-note choices append global meta tags; selected ranges allocate the first unused `{}`/`[]`/`()` scope at depths 1–3, wrap the selection, and append the matching scoped tag. Basic formatting scopes can cross, while renderer tags are available globally or scoped.
  - **Remove Formatting** and `Cmd/Ctrl+U` are selection-aware: a selected range is unformatted locally, removes intersecting inline images, and splits surrounding scopes to preserve styles outside it; with no selection, the server strips rich HTML and all inline images while preserving links, removes Add Style tags, and removes retired scope delimiters without disturbing scopes still used by ordinary wrapped tags.
  - Unfinished tag-bar scopes permit inner-prefix autocomplete (`{{@` suggests meta tags); a subtle close-wrapper reminder starts after inner-tag whitespace while autocomplete remains available for additional scoped tags. Accepting a suggestion preserves open delimiters, and blur still drops incomplete scopes.
  - Tag bar grammar (wrappers + /* comments */): `docs/ui/tag-bar.md`.

## Runtime Storage Contract
- MetaList is memory-first after startup/hydration: SQLite is persistence, not the runtime read path.
- Startup or post-login hydration loads required namespace data from SQLite, decrypts it if needed, and populates service-owned in-memory stores/caches.
- Normal app reads must use in-memory stores/caches. View rendering and `/api2/notes/view` must not perform SQLite reads.
- Mutations update in-memory state and write encrypted-at-rest rows to SQLite. SQLite is effectively write-only after startup for normal runtime behavior.
- New persisted namespace features should follow the same pattern: schema + load-all bootstrap + service cache + write-through encrypted persistence; do not add runtime DB lookup paths.

## Gotchas / Open Issues

- Tagging focus is separate from vocabulary permission: broad requests ask existing/new/both when new tags are allowed; explicit focus skips clarification. Focus applies only to the current pass. Existing-only permission is never overridden by inferred intent or a focus answer.
- Removing the `app/services/store.py` adapter and calling `NoteStore` directly from all usecases still exposes referential integrity issues in some undo flows (delete/move). Adapter remains; revisit with tighter invariants + targeted tests.
- Search is server-side + indexed: `app/services/search_index.py` (tag postings + trigram postings over `strip_html(content)`), used by `app/services/snapshot.py` to filter `/api2/notes/view`.
  - Query terms: unquoted tokens are tag terms; quoted strings are text terms. Exact uppercase unquoted `OR` separates implicit-AND clauses, with forbidden terms scoped to their clause; uppercase `OR` is reserved from tag creation (see `docs/ui/search-syntax.md` + `docs/ui/search-semantics.md`).
  - Search syntax does not provide created/updated date constraints.
  - Views remain windowed (roots chunked; infinite scroll extends as needed).
- Root sorting helper: `app/services/root_sorting.py` centralizes sort-mode normalization, subtree-max root timestamps, HTML-stripped subtree content-volume totals, server-side root ordering, and date-bucket metadata for the client.

- AI tagging: explicit chat requests select `tag_proposals`; `app/services/agent/tagging.py` + `tagging_run.py` capture visible trees including ancestor content, randomize root order before token-sized batching, enforce shared context-wide accepted vocabulary, and collect structured proposals before atomic application through `app/usecases/bulk_tag_proposals.py`. Root hierarchy/order remains intact. New tags from completed batches are optional reuse vocabulary for later batches but remain unaccepted. Successful completion groups newly added tags with clickable citations to affected notes and replaces the reference disclosure with one **Show all new tag proposals** combined-view link; history retains tag names, while later tagging reads authoritative per-note pending proposals and excludes duplicates. Above 1× evidence budget, ask confirmation; show elapsed time/progress without duration estimates. UI locks and `app/services/bulk_operation.py` blocks conflicting server mutations until completion/cancellation. Every broad request shows the existing-only/new-only/both selector, preselects its exact remembered choice, and updates the two-way vocabulary permission from that answer; menu edits the permission and tagging prompt. Bulk accept/remove supports context/namespace plus exact tag filter from chat or menu; a separate menu command confirms before removing every current-context suggestion. These clear undo/redo only after changes and create no undo entry. Successful changes also discard the active root window and reset its infinite-scroll terminal state before a required fresh view fetch. No rejection memory or automatic generation. Provider-specific batch windows are configurable in AI settings. Progress measures completed batch input tokens.
