## Enforced standards (September 2026)
- Performance overlay retired: refresh/scroll paths no longer cache or render overlay metrics. Client-state normalization discards its obsolete preference and command usage; legacy browser migration clears its stored toggle.
- Client state owner: `app/static/js/modules/application-state.js`. Controllers/module fields use owned getter/setter records; preference/modal scopes expose immutable snapshots. Equal writes and redundant collection mutations throw. `ModeContext` remains the note/mode facade.
- Snapshot reconciliation is limited to reviewed observation boundaries in `app/startup_sanity_config.py`; actual transitions stay strict. Modal scopes require initialization/disposal; `CommandGate` exclusively owns command loading.
- Python capture boundaries/types: `app/exception_boundaries.py`; domain request exceptions: `app/services/input_errors.py`. Internal exceptions propagate. JS expected failures: `expected-errors.js`; rejected promises and inline maintenance handling are covered by startup checks.
- Tests: Python and Node unit suites; disposable namespace/browser smoke in `scripts/browser-smoke.mjs`. Detailed contract: `docs/ui/state-handling.md`.
- Tab scroll persistence: one poll/save at a time; snapshot writers wait for the preceding version/signature update before reading current state. Delayed-response regressions cover duplicate polls, concurrent saves, movement/tab switches during saves, and failure cleanup in `tab_state_service.test.mjs`.
- Version Info uses a wait cursor across the modal/backdrop during update admission, preparation, installation, and restart polling; completion/failure restores normal cursors. Cursor styling follows rendered job state and disappears when the modal closes.
- Lifecycle regressions: editor/tag focus transfers consume one selection record; bulk completion distinguishes absent from unchanged; cleanup releases only owned timers/requests. `tag_bar_focus_lifecycle.test.mjs`, `state_transition_regressions.test.mjs`, and `scripts/browser-state-regressions.mjs` cover repeated interactions without relaxing strict setters.

## Project: MetaList
- Single-user FastAPI app for hierarchical notes with SSR + a diff-based `POST /api2/notes/view`.

## Architecture
- Entry: installed CLI `metalist` → `main.py:main()`; both plain `metalist` and source-checkout `python main.py` bootstrap every known namespace and exit after printing the per-namespace URLs. Explicit namespace/port arguments are forwarded by the installed console wrapper into the same parser.
- Packaging: `app/version.py` is the single `0.7.1` version source consumed dynamically by `pyproject.toml` and runtime config; the package includes templates/static assets plus agent prompts/skills Markdown. Installed helper commands include `metalist-audit-encryption`, `convert-from-legacy.py`, and `generate-lan-cert.sh`. Runtime imports support Python 3.10 via `timezone.utc` and explicit `typing_extensions.Self`.
- Release workflow: `.github/workflows/publish-pypi.yml` validates branch pushes and PRs; `scripts/check_distribution.py` compares runtime files in wheel/sdist with source and imports packaged agent resources outside the checkout. Hosted Windows/macOS/Linux × Python 3.10–3.14 jobs install the wheel, check dependencies, and run `scripts/smoke_installed_package.py` (the real installed metalist executable, parent/child namespace orchestration, two HTTP/HTTPS namespaces, auth/version status, HTML/static assets, and disposable data roots). Before creating any release tag, require all checks successful for the exact candidate commit. Tag/manual publication repeats gates and publishes the same tested artifacts via GitHub Trusted Publishing; ordinary branch/PR runs cannot publish.
- In-app updates: each `main.js` document load starts public, uncached `/auth/app-update/check` before auth; a late response can show a reminder-style card after readiness. Per-namespace `pref.update_notice_version` suppresses repeated notices. Menu `update`/`upgrade` finds Version Info, which checks again and offers installation only for managed uv copies. Authenticated POST pins the reviewed release and queues a detached `app_update_worker`; an OS file lock serializes admission across namespaces, and opaque job polling survives lost authentication/restart. Worker clears child namespace/port flags while retaining LAN/TLS/data settings, delegates to the existing updater, and exits before code replacement. UI resumes jobs when the modal reopens within the same page; post-stop failure needs log inspection/manual restart, no automatic rollback.
- Self-update: `metalist update` → `self_update.py` checks PyPI version/prerequisites, then `update_preflight.py` delegates a disposable candidate tool install to uv with the running interpreter's external base path. It checks interpreter/version identity, dependencies, real temporary HTTP startup and static assets before stopping any live namespaces. Windows probe cleanup stops and waits for the launcher’s descendant processes before deleting temporary files. It freezes tested dependency versions, stops namespaces, creates/verifies new immutable backups, then hands off to a POSIX shell or Windows PowerShell for offline uv installation and real namespace restart. No backup retention or archive mutations; no automatic database/code rollback. Preflight uses only disposable data and cannot prove startup against every real database. `scripts/smoke_self_update.py` tests the candidate updater in an old-version fixture through a local release index, real uv install, backups, and two HTTP/HTTPS namespace restarts; all 15 release matrix jobs require it. Earlier installed updaters retain their old behavior until upgraded.

- Prelaunch gate: `main.py` resolves `METALIST_ENVIRONMENT` from the process environment or the ignored repository-root `.env`, prints `development`/`production`, and runs Python + JS startup sanity checks once in the parent process only in development. Missing configuration means production. Python rules live in `app/startup_sanity.py`; JS rules live in `app/startup_js_sanity.py` and forbid native browser `alert`/`confirm`/`prompt` dialogs so user communication stays in MetaList UI; shared constants live in `app/startup_sanity_config.py`.
- Startup bootstrap: the installed `metalist` command creates `~/MetaList/namespaces/default/default.metalist.db`, its default settings row, and suggested launch profile only when no namespaces exist. A deleted `default` stays deleted while another namespace exists; deleting the final namespace recreates a fresh `default` on the vacated ports. `main.py` resolves `--namespace`, positional namespace shorthand (`metalist cla` or `python main.py cla`), `--port`, `--https-port`, and the non-persistent `--enable-shell` capability before importing `app.main`, so explicit single-namespace launches still expose the right DB path and listener ports at import time. All-namespace launches propagate `--enable-shell` to every child, force the default host to loopback, and print a conspicuous top-level enablement banner.
- Machine network settings: `app/network_settings.py` saves explicit `METALIST_HOST` / `METALIST_ALLOWED_HOSTS` in the data-root `network-settings.json`; source, installed CLI, and updater load them before application config imports. Explicit environment values replace saved fields. Fresh installs stay loopback-only; shell flags and namespace ports are not stored here. Strict host validation lives in `app/security/request_hosts.py` so early settings loading cannot freeze namespace config. Installed-package and self-update gates verify non-loopback HTTP/HTTPS after a CLI restart with network overrides removed; Edge uses that restart too.
- Namespace launch profiles: `app/server_runtime.py` stores remembered per-namespace HTTP / HTTPS ports as plaintext metadata in each namespace's main `*.metalist.db`; the old global `~/MetaList/namespaces.db` registry is ignored. Schema-v1 `mcp_port` values remain inert compatibility metadata only.
- AI/agent boundary: Authenticated chat uses an application-owned read-only investigation loop plus explicitly requested bulk tag proposal operations. Every request carries required visible-tab and originating-scope-tab IDs; the server verifies the visible tab, then filters canonical search/sort matches through the provider disclosure boundary before freezing immutable `S0`. `@password` always removes its complete subtree. OpenAI/future cloud providers additionally share one namespace policy with OR whitelists, OR blacklists (blacklist wins), case-insensitive literal phrases, and canonical effective-tag matching including inheritance plus ontology implications/synonyms; Ollama ignores those configurable lists. Hidden ancestors always hide descendants. Filtering precedes counts, evidence, citations, debug, and provider prompts. Hovering chat calls the same server evaluator and marks hidden notes with readable gray backgrounds. A temporary Reference source is navigation, not a new evidence scope, so follow-ups retain the search that produced the answer even while the reference remains open. A later AI-reference click replaces that active temporary query, while ordinary note-internal reference following still stacks. Route selection receives a trailing content-free `ROUTE_SELECTION_REQUEST` with the exact current request, user-driven query, scope metadata, and note/root counts; explicit saved-note requests cannot validate as `respond`, while corrections/challenges default to direct conversation unless they explicitly request fresh note evidence. Instructor routes `respond` vs. `investigate_current_scope`. Investigation lazily walks complete roots in canonical order, retains the longest leading prefix within one provider-specific evidence-token limit, and sends exactly one compact recursively nested payload directly to final generation. Roots never split; retained note content is complete; later roots are omitted and exact included/omitted counts prevent exhaustive claims. There is no multipage loop, working summary, facet browser, tag narrowing, ranked-source memory, or source-rehydration pass. Ollama defaults to 5,000 evidence tokens (range 500–24,000); OpenAI defaults to 250,000 (range 500–500,000). Final prose is capped at 1,024 tokens for Ollama and 8,192 for OpenAI; a provider-reported length stop fails visibly. OpenAI uses `store: false`; protected namespaces persist its key encrypted while plaintext namespaces hold it only in server session memory. Scope/actions/evidence/traces are session-only and never canonical history. Full contract: `docs/design/agent-harness.md`.
- Namespace switching/launching: `app/services/namespace_switcher.py` lists known namespaces, suggests ports that avoid both saved namespace reservations and active OS listeners, and automatically repairs duplicate saved profiles during all-namespace startup (default first, then alphabetical), persisting the reassigned ports and printing a concise before/after warning. It reuses an already-running target with a warm cache when its saved launch profile is unchanged, restarts it when requested ports changed, relaunches the recorded entrypoint (installed CLI or source script), rejects launch-time listener races without terminating the port owner, and writes child logs under `~/MetaList/logs/`. `app/services/namespace_runtime_guard.py` revalidates each non-test process's namespace DB/profile identity every five seconds and self-terminates if that identity disappears. Windows listener discovery and process termination use built-in PowerShell through `app/services/windows_process_control.py`; macOS/Linux retain the POSIX `lsof` and signal path. Plain all-namespace orchestration deliberately restarts namespaces to pick up current code.
- Child entrypoint: `serve_namespace.py` is the namespace-serving source entrypoint; installed child launches carry `METALIST_ORCHESTRATED_CHILD=1`. Both paths bypass parent-only sanity checks and the already-completed all-namespace encryption audit, preventing false readiness timeouts on large Windows vaults. The parent tracks the child process, flushes child output, reports progress every five seconds, and allows 120 seconds (positive integer `METALIST_STARTUP_TIMEOUT_SECONDS` override). Early exit fails immediately; any failed readiness wait terminates/reaps its owned child. Failure includes the current child log tail.
- HTTPS proxy: the pending accept queue matches the existing 32-worker capacity; the unchanged six-client TLS regression caught sixth-handshake resets with the inherited five-entry queue during 0.6.3 preparation. `main._HttpsProxyServer` binds directly through `TCPServer` and records the bound host/port without an unnecessary reverse-DNS lookup; slow hostname resolution must not block namespace startup. `app/https_proxy.py` preserves browser HTTP/1.1 connection reuse across module/API requests; chunked streaming, idle timeouts, explicit client closure, and closure after transport failure keep framing bounded.
- `app/main.py`: FastAPI wiring, middleware, startup bootstrapping, SSR templates. Static assets and Mako templates are served directly from `app/static/` and `app/templates/`; Python auto-reload remains disabled, so rerun `main.py` to load Python changes.

## Design
- Modal dismissal: `BaseModal` injects a standard upper-right circular `×` after every full-content render; `×`, `Escape`, and outside click share the same close request path. Dismiss-only `Close`/`OK` footer buttons are not used, while workflow `Cancel`/`Back` actions remain.
- Pattern: usecases (Cmd*) orchestrate services; services encapsulate DB work + undo logging.
- State: Notes stored as parent/prev/next pointers; decrypted cache is preloaded; sync UUIDs/locks managed in `app/services/sync.py`; active tabs/search/scroll are snapshotted via `tab_state_store` into the namespace DB so reopening the app or restarting the server restores the last view; command-palette prefs/usage are persisted per namespace in `app_settings` instead of browser `localStorage`. `Note Layout & Appearance…` uses those prefs for root-note size (default `Larger`), child indentation, and vertical spacing; visible list tags wrap within 25% of the note row. Every note context menu ends with a non-interactive dark footer showing locally formatted `Created` and `Updated` timestamps; the former hover-popup preference is obsolete.
- Root sort modes: per-tab server-owned `sortMode` (`normal`, `created`, `updated`, `alphabetical`, `content-volume`) lives in `app/services/tab_state.py`; created sorts roots by their own creation timestamp; updated uses the newest timestamp anywhere in each root subtree, alphabetical mode sorts by root content, and content-volume mode sorts largest-first by summed HTML-stripped character counts across each entire root subtree. Equal volume totals preserve canonical root order. The client renders day separators from `snapshot.rootSortBuckets` only for datetime modes. Background/side-rail context menus expose all five modes via Sort by, using the same saved per-tab setting as the command palette.
- Untagged view: transient client-owned `isUntaggedView` is a tab-agnostic display override selected through `View: Untagged notes`/`View: All notes` and shown as a dismissible pill. It preserves the underlying tab/search and matches notes with no non-meta effective tags, so inherited and ontology-inferred classifications exclude a note while `@` formatting/meta tags do not. Clicking any tab or changing search dismisses it.
- Bulk expand/collapse: command-palette Expand All and Collapse All update only root notes in the active search context; descendant collapse states are preserved.
- Per-note collapse affordances: the server marks notes with children as collapsible; the browser also promotes rendered content that occupies multiple visual lines. Inline fragment rectangles that overlap on one visual line are grouped together, preventing mixed-size title/domain link markup from creating a false collapse arrow.
- Mutation safety: mutating FastAPI routes are expected to carry `@transactional_route`; startup sanity enforces the decorator ordering in source, and request-scoped write sessions commit once at the end of the wrapped request path.
- Diff caching: Server caches each `(client, tab, search)` view and the client keeps per-tab note-hash maps so `/notes/view` diff payloads stay scoped to the active tab.
- Filtered edit cleanup: refresh checks the updated note-hash membership before reattaching the editor. Removed notes can remain in the DOM during removal animations; they must immediately lose editing selection and tag-bar/toolbar state.
- Tab switch perf: Client can detach/cache the `#notes-container` subtree per tab and restore it instantly on return, then call `/notes/view` to reconcile small diffs.
- Client busy model: `CommandGate.run(name, asyncFn)` is the single boundary for user-initiated server calls; it is the only code allowed to flip `ModeContext.isLoading`.
- Undo boundaries: client includes an `epoch` in `undoContext` (`tab/search/epoch`); global actions bump the epoch so undo/redo cannot cross those boundaries. Selection/deselection is not recorded: application undo/redo traverses saved mutations only. While editing, undo and `Cmd/Ctrl+Shift+Z` redo remain browser-native; `Cmd/Ctrl+Y` is mapped client-side to the active editor's local redo command. Sort-mode changes are global boundaries and blank undo/redo for the active tab context. Search input changes dismiss transient views and reset sort to Normal before execution.
- Error handling: fail-fast (internal errors crash; DB rollback triggers immediate process exit; request-validation crash toggle). Browser HTTP `4xx`/`5xx` responses report request/server failures without marking the client disconnected; only transport failures disable editing and enter the persistent soft-amber reconnecting state. Expected transport rejections bypass the fatal red stack overlay, while unexpected client exceptions still surface there.
- Auth: Argon2id password verifier protecting the DEK; encrypted settings require `vault_version` + full KDF profile (`kdf_algorithm`, `kdf_memory_cost_kib`, `kdf_parallelism`); new/changed passwords require 12-72 characters and offline zxcvbn score >=3 while existing passwords remain valid; `/api2/auth/login` is rate-limited; public routes use an exact-path allowlist (prefixes only for static files and opaque job polling), and production does not mount `/dev` DB-switching routes; pre-login namespace selection uses `GET /api2/auth/login-namespaces` + `POST /api2/auth/login-namespaces/open` without widening the authenticated namespace APIs; tokens are kept in-memory on the namespace server and default to no idle expiry, while the browser carries them in namespace-scoped HttpOnly `metalist_auth_<namespace>` cookies instead of `localStorage`; token issuance enforces one active session per namespace while allowing different namespaces to remain open together. Browser API/state debug output is disabled by default and shared loggers discard caller-provided payload/state values.
- Password generator: browser-only CSPRNG using `crypto.getRandomValues()` with rejection sampling; custom alphabets deduplicate Unicode code points, and requested length counts code points rather than UTF-16 units. The generator lazy-loads the vendored official zxcvbn JavaScript build and displays its 0-4 score without sending generated passwords to a scoring endpoint.
- Shell security: `CmdRunShellStart` and `CmdRunShellStatus` reject execution/output access unless `--enable-shell` was supplied and password protection is enabled for the active namespace. HTTP routes require both a loopback client and loopback request host, allowing normal LAN note access on a wildcard bind without exposing shell; start rejects before loading the note or reaching the host-process service.
- Browser content security: every response receives a nonce-based CSP that permits scripts only from MetaList itself or the per-response nonce, restricts browser fetch/XHR/WebSocket connections to same-origin plus local `data:`/`blob:` resources, blocks objects/frames/base-tag replacement, and adds `nosniff`, deny-framing, no-referrer, restrictive permissions, and `Cache-Control: no-store, private` headers. Inline startup scripts carry the generated nonce; inline styles remain enabled for the current editor/rendering contract.
- Request boundary: listeners default to `127.0.0.1`; requests accept only loopback, the specific bind address, or `METALIST_ALLOWED_HOSTS`. Unsafe browser requests require an exact same-origin `Origin`; cookie-less bearer clients may omit it. `X-Forwarded-Host` is ignored, while Uvicorn trusts forwarded scheme/client metadata only from `METALIST_FORWARDED_ALLOW_IPS`.

## Workflows
- View/diff: `POST /api2/notes/view` → `app/services/snapshot.build_view_state()` → cold cache returns `snapshot.structure`, warm cache returns `snapshot.diffOps`, both with sparse `notes` + locks. Snapshot hierarchy/metadata share request-local traversal caches; identical structures skip branch diffing, and client no-op/lock-only diffs skip media scans.
- Root sorting: `POST /api2/notes/tab-state/sort-mode` updates per-tab sort state; subsequent `POST /api2/notes/view` responses echo `sortMode` and `rootSortBuckets`, and the client inserts ephemeral date separators between visible roots for datetime modes.
- Embedded references: view payload `notes[*].content` can include rendered `![[UUID]]` blocks (view mode only). Expanded hosts render the referenced root and its complete descendant subtree regardless of source collapse states, with no inner collapse controls and an arrow-only ↗ source link at the top-left; collapsed hosts reduce note embeds to compact source links retaining first-line footnote superscripts. Source links and reference context-menu `Go to Source` open a temporary duplicated tab whose UUID query is hidden behind a dismissible `Reference source` indicator; dismissing it returns to the originating context, preserves that tab's root/infinite-scroll tracking, and closes the temporary tab, while typing a search converts it into a normal search tab. Sole note references use the entire host background without an inner panel. `NoteStore` owns a memory-only `backlink_index.py` (source/target UUIDs + occurrence counts), built during hydration and maintained on content/accepted-tag edits, add/delete, and bulk-tag changes; reset/lock clears it and reload rebuilds it. Collapse and snapshots reuse constant-time source membership; backlink listings reuse counts and read previews only for referrers in current tree order. `reference_presentation.py` adds a ↖ source button opening a deduplicated namespace-wide `Referenced by` temporary view; ×/Escape return to the previous context. Reference mode is registered before tab activation so internal UUID queries never flash in the search field. View-indicator transitions skip note animations; scroll restoration preserves exact top position and discards pending restores after view resets. Host note hashes include rendered embed output and source-arrow presence.
- File attachments: `POST /api2/files/upload` stores the uploaded file in `*.files.db`, returns a UUID token, and the client inserts `![[UUID]]` into the active note (or a newly created note when none is active).
- File downloads: rendered file references in view mode call `GET /api2/files/{file_id}/download`; metadata/blob rows are decrypted on demand rather than at startup.
- File trimming: `POST /api2/files/trim-unused` deletes attachment rows no longer referenced by any note; removing refs does not auto-delete files so undo/redo remains safe until trim runs.
- Tag persistence: tags are included in `snapshot.notes[*].tags` and are saved alongside note content on `PUT /api2/notes/{id}/save`; inferred search-only tags like `@image` are computed for the search index and are not shown in the tag bar. Tag-bar mouse/keyboard focus gets a persistent soft ring plus one subtle halo when Animated Transitions is enabled; reduced-motion and disabled-animation states keep only the static cue.
  - Selecting up to 25 characters in a note exposes **Add as Tag** in its context menu. `POST /api2/notes/{id}/add-selected-text-tag` reuses the most frequent explicit namespace tag across case and space/`-`/`_`/`.`/`/` joiner variants, or creates a sanitized case-preserving dash-joined tag, then applies it only to that note.
  - Right-clicking the actively edited note exposes an **Add Style** flyout. Whole-note choices append global meta tags; selected ranges allocate the first unused `{}`/`[]`/`()` scope at depths 1–3, wrap the selection, and append the matching scoped tag. Basic formatting scopes can cross, while renderer tags are available globally or scoped.
  - **Remove Formatting** and `Cmd/Ctrl+U` are selection-aware: a selected range is unformatted locally, removes intersecting inline images, and splits surrounding scopes to preserve styles outside it; with no selection, the server strips rich HTML and all inline images while preserving links, removes Add Style tags, and removes retired scope delimiters without disturbing scopes still used by ordinary wrapped tags.
  - Unfinished tag-bar scopes permit inner-prefix autocomplete (`{{@` suggests meta tags); a subtle close-wrapper reminder starts after inner-tag whitespace while autocomplete remains available for additional scoped tags. Accepting a suggestion preserves open delimiters, and blur still drops incomplete scopes.
  - Tag bar grammar (wrappers + /* comments */): `docs/ui/tag-bar.md`.
- Suggestion behavior: search-bar and tag-bar suggestions are segment-aware for connector-separated tags, collapse case-equivalent tags to one displayed spelling, combine a typed tag prefix with literal matches for the remaining tag segments, recognize near-complete numeric connector phrases such as `5.6 sol` without accepting numeric-only noise, and can suggest ontology tags that have never been explicitly used on a note; actual search filtering remains exact on effective tag terms. Numeric-only chunks do not increase required content coverage: `gpt-6-astra` behaves like two chunks, so `Astra` alone qualifies; numbers still contribute to full/partial phrase ranking.
- Tag suggestion ranking: one-character non-meta tag-bar prefixes put real co-occurrence hits from explicit/inherited context first, then exact current-note literals, then use case-insensitive raw note frequency (explicit assignments plus hierarchy/reference inheritance, excluding ontology implications) for the fallback; longer prefixes retain content/context ranking. Tag-bar suggestions otherwise interleave top literal content hits with top direct co-occurrence hits from the current explicit tags, prioritize exact standalone literals over synonym-expanded recommendations, suppress blank-prefix content variants already covered by an explicit/inherited tag segment, treat connector-separated partials literally (`Y-Z` before `X-Y-Z` for `Y Z`), prefer structured/longer entity hits like `CookUnity` over shorter plain-word hits like `meal` when content-hit strength otherwise ties, collapse ontology-equivalent suggestions to the most-used explicitly written tag-bar synonym rather than inferred search frequency, and can show an exact content-matched synonym alias immediately after its common representative. Server caps are `MAX_SEARCH_SUGGESTIONS` and `MAX_TAG_SUGGESTIONS`.
- Tab persistence: browser boots, `tab-state-service.js` fetches `/api2/notes/tab-state`, hydrates ModeContext, throttles scroll/search changes, and POSTs back when they differ; the server persists that snapshot per namespace in SQLite and rewrites it between plaintext/encrypted storage when password protection is toggled.
- Client-state persistence: browser boots, `auth.js` reads theme from `/api2/auth/status` when unlocked, `command-palette-controller.js` loads `/api2/auth/client-state`, migrates legacy browser `localStorage` once, and persists future preference/usage updates as plaintext only in passwordless namespaces or as DEK ciphertext in encrypted namespaces.
- Busy gating: keyboard/mouse/search/autosave actions call `CommandGate.run(...)` → server API calls → `actionRefreshAndMaybeSelect()`; background pollers skip ticks while `CommandGate.isBusy()`.
- Edit focus styling: `app/static/css/main.css` uses `#notes-container:has(.note.editing)` to slightly blur non-editing note content/toggles outside the edited note subtree, including ancestor content, while keeping the edited note and its children sharp.
- Test harness boundary: `POST /api2/test/reset` clears DB/tag-activity/cache/tab/auth/sync state, and `app/static/js/main.js` exposes `body[data-app-ready="true"]` after `Auth.init()`, `ModeManager.init()`, and `CommandPalette.init()` complete.
- Reference shortcut: `Cmd/Ctrl+R` copies as embedded reference (`![[UUID]]`) from the last note copied with `Cmd/Ctrl+C` (when no text selection).
- Note clipboard: `Cmd/Ctrl+C` with no text selection stores the note subtree server-side and writes promised `text/html` + tab-indented `text/plain` to the system clipboard; `Cmd/Ctrl+V` into an empty target note replaces that target, preserving/merging its context tags with copied root tags via case-insensitive dedupe.
- Split shortcut: `Cmd/Ctrl+S` sends one server-side split command for the currently edited note, records one undo/redo step, and preserves the original tag-bar string across all resulting notes; caret at the front creates a blank note above, caret at the end creates a blank note below, split normalization trims edge-empty nodes, and full-note selection remains a no-op.
- Move-to-top shortcut: `Cmd/Ctrl+Shift+Up` is server-driven; a selected root note moves to the top of the current root view (including filtered/search views), while a child note moves to the top of its sibling list.
- Command palette help action: `Cmd/Ctrl+/` → `Keyboard shortcuts / cheatsheet…` opens the cheatsheet modal from palette utilities.
- Version/migrations: `app/db/migrations.py` owns ordered `PRAGMA user_version` upgrades (current DB version `9`). Passwordless namespaces migrate at startup; encrypted namespaces create a new pre-migration snapshot and migrate the live DB after successful DEK unwrap. Version 3 removes deterministic search-history metadata; version 4 discards incompatible query scores and starts one row-bound encrypted sparse daily tag-activity aggregate; version 5 adds encrypted OpenAI credential columns to `app_settings`; subsequent migrations retire obsolete data through version 9, which removes live sound storage/settings. Migration purges only live SQLite/WAL residue; historical backups are never rewritten. App version, DB schema version, vault version, and named content-migration identities are independent.
- Version inspection: `Cmd/Ctrl+/` → `Version info…` opens a read-only modal backed by `/api2/auth/status`, showing app version, SQLite `PRAGMA user_version`, namespace, auth/encryption/vault/KDF state, and cache readiness.
- Encrypted login progress: password submission immediately shows the progress panel for database checking/upgrades, displays total elapsed time, and always continues through `/auth/hydrate`, even when no rebuild is required. Initial hydration copy describes the in-memory work without incorrectly implying that every cache rebuild proves a restart; the duplicate page-level loading subtitle is hidden while that panel is active.
- View visibility: `Cmd/Ctrl+/` exposes dynamic Tabs, AI Chat, and Tags in List toggles; right-clicking either lane or the notes-view background provides the same persisted visibility controls outside edit mode. Chat defaults to a resizable right third and narrows the notes shell; the transcript is server-memory session state while width is a persisted client preference that is temporarily viewport-clamped without overwriting the saved choice. Right-clicking a completed assistant response copies its raw Markdown into the note clipboard with `@markdown @llm` and writes rendered HTML/raw Markdown to the system clipboard; it can paste as a note but cannot paste as a reference until inserted. AI Agent Settings selects MetaList-managed Ollama or OpenAI API. Ollama uses one shared daemon on `127.0.0.1:11435`, launched on demand with cloud disabled and a 32,768-token context; it can explicitly download a named model through Ollama's supported pull stream, with live progress and no registry scraping. Runtime PID ownership/state is shared across namespaces in `~/MetaList/runtime/ollama/`, the managed log is `~/MetaList/logs/ollama-managed.log`, and every Ollama run verifies the selected model's active context before inference. OpenAI settings accept a write-only API key and a supported model; encrypted namespaces persist the key encrypted, while plaintext namespaces label it session-only and lose it on logout/session replacement/server restart. When enabled, tabs expose a white outline stacked-folder icon in the black left hover trigger, with its left inset mirroring the results count's right inset; the overlay remains open when hover-triggered `Enter` creates a blank tab, and visible search suggestions stack above it. Tab order uses native row drag/drop: dropping a tab over another moves it into that row's former slot and persists `tabOrder`; the grabbing cursor appears only during an active drag, and the old arrow controls are removed.
- Modal visual/interaction contract: application modals use the theme-independent dark shell and shared control/button/surface tokens in `app/static/css/main.css`; feature CSS should add only justified widths/layouts, keep short values compact, and stack forms on narrow screens. The ontology editor and its sub-dialogs are an explicit exception that retain their established standalone visual system. Every app menu/modal closes with `Escape` or an outside click; `Enter` activates the selected menu action or the modal's declared primary action. Ontology relationship add/edit suggestions open with no automatic selection (one Down Arrow selects the first); plain `Enter` submits while untouched suggestions are visible, but an explicitly arrowed or pointer-chosen suggestion makes the next `Enter` accept that suggestion without submitting; clickable submit buttons remain. Opening a modal while editing runs the normal save/deselect/view refresh first so view-only note HTML (including cached URL-title rendering) is restored before the modal appears.
- Login screen namespace switcher: the bottom login picker lists plain namespace names (`default`, `cla`, etc.), opens the selected non-current namespace in a new browser tab through the login-only namespace-open flow, and lands directly in passwordless namespaces because the destination page auto-claims a passwordless session on load.
- Namespace commands: `Cmd/Ctrl+/` exposes separate modals for switching, creating, renaming the current namespace, managing ports, and deleting a namespace. Switching leaves the current namespace open and launches the selected non-current namespace in a new browser tab; tab-bound tokens still enforce one active tab/session per namespace. Rename rejects an existing target name, moves the namespace directory plus its main/files databases and backups, preserves its launch ports, restarts on those ports, and requires a fresh login. Deletion requires exact namespace-name confirmation but never the namespace password, allowing an inaccessible encrypted namespace to be removed. Active deletion requires the user to choose the redirect namespace; deleting the final namespace recreates a fresh `default`. Port management saves launch profiles only, so current-namespace port edits apply on the next launch.
- External paste/drop: `keyboard-events` routes non-note clipboard HTML through `sanitizeAndInsertExternalPaste()`; only explicit **Copy note** HTML carries the `data-metalist-note-clipboard="true"` marker, so copied selections/URLs containing ordinary `note-content` markup are not mistaken for structural note paste. The structural clipboard is server-memory state, and expiration after restart returns a nonfatal copy-again result. Clipboard image pixels embed as compressed `data:image/...`, while named pasted/dropped image files can either embed inline or be saved as file attachments via a choice modal. Remote HTTP(S) `<img>` URLs remain encrypted note content: document CSP blocks direct browser loads, paste/edit registration substitutes opaque same-origin `/api2/remote-images/{token}` references for immediate editor display, storage serialization restores the original URL, and the authenticated in-memory proxy fetches only SSRF-validated public targets with redirect/type/size limits without persisting image bytes.
- View-mode links: rendered anchors open in a new browser tab without selecting/dragging their host note; editor links retain editing behavior. Standalone bare URLs and URL-only HTML/Markdown anchors use cached `title · domain` labels; custom labels remain intact. Compact note-reference previews reuse title/domain formatting. `link-title-prefetch-service.js` observes editor drafts on the 500 ms inactivity loop, waits for a 600 ms pause, and calls authenticated `POST /api2/notes/link-titles/prefetch`; `CmdPrefetchLinkTitles` reuses view formatting to enqueue eligible lookups without saving or rewriting the editor. Deselect requires a completed view request; revision-driven refreshes defer while editing and require execution afterward. Unknown/failed URLs remain raw with hover diagnostics until a successful background result arrives.
- Image file refs in view mode: embedded image attachments render as authenticated previews with a `download image` control; collapsed notes reduce them to a compact thumbnail.
- Image sizing/context menu: right-clicking a rendered image adds non-destructive `Make Bigger`, `Make Smaller`, and `Reset Size` actions alongside copy/save/zoom/open. Size changes step through scoped `@size=0.1`–`@size=3.0` tags, apply immediately in view mode, remain raw/visible while editing inline images, and work for stored image-file embeds in view mode; Reset removes the size tag and delimiters no longer owned by another scoped tag.
- Note full-screen view: outside edit mode, a note context-menu action opens a read-only edge-to-edge rendering of that note plus every descendant (even when the source note is collapsed), omits ancestors, hides the menu/scroll-to-top controls, and exits by the upper-right `×` or `Esc`. `GET /api2/notes/{id}/fullscreen` builds the subtree markup from the in-memory store.
- Prioritize root notes by tag: `Cmd/Ctrl+/` → `Prioritize tag to front/back (global)…` opens an app-styled warning, then permanently rewrites global root-note order so all roots matching the selected tag move to the requested end while preserving internal order; Cmd+Z cannot undo it because the command bumps the undo epoch and the server clears that undo context.
- Alphabetize root notes: `Cmd/Ctrl+/` → `Alphabetize root notes A-Z/Z-A (current view)…` opens an app-styled confirmation, then permanently rewrites only root-note order within the active search context by root content; Cmd+Z cannot undo it because the command bumps the undo epoch and the server clears that undo context.
- Timestamp repair: `Cmd/Ctrl+/` → `Repair: reset updated time to created time (current view)…` opens a confirmation, then sets `updated_at = created_at` for every note inside each matching root subtree in the active search context; outside roots are untouched, and the undo context is cleared.
- Backup/restore: `app/services/backup_service.py` exclusively creates the notes DB plus sibling files DB as one versioned `.tar.gz`, validates manifest checksums/format on restore, hashes restore sources before/after to enforce byte immutability, rebuilds the file registry afterward, ignores legacy search-history sidecars, and still restores legacy `.bak` snapshots. Existing backups are never rewritten/repackaged; `BKP001` startup sanity enforces the boundary. Old versions migrate only on the installed live copy (immediately if plaintext, after unlock if encrypted). Same-name and different-name restores retain an existing target's launch profile; new targets receive conflict-free ports. Restore UI never edits ports.
- Backup settings: `GET/PUT /api2/backup/settings` reads or explicitly updates the configured folder path, selected namespaces, and per-namespace retention count. The normal `Back Up Now` path does not perform a settings-only preflight request.
- Backup run: `POST /api2/backup/run` requires the submitted folder/namespace/retention settings, persists them and creates one archive per selected namespace in the same backend operation, applies retention, and reports one concrete result row per namespace. The result modal is never shown from a settings-save response alone.
- Backup/restore scope: backup listing/creation/restore are scoped to the active DB path; namespaces live under `~/MetaList/namespaces/<namespace>/` and back up into `~/MetaList/namespaces/<namespace>/backups/` with filenames like `<namespace>-<timestamp>.metalist-backup.tar.gz`.
- Reminders: `Cmd/Ctrl+/` → `Reminders…` opens the in-app reminder registry/builder. Current implementation is standalone-only; note attachment is deferred until there is a real note picker/search flow rather than raw UUID entry. Reminders can be one-time or recurring, date-time or date-only, include optional details, include at most one optional pre-reminder, and either drop if missed or stay visible until seen. Date-only reminders fire only on first non-idle app use for the local date. Day-based pre-reminders are also date-only prompts; minute/hour pre-reminders are exact offsets for date-time reminders only. The client refreshes its mirror after reminder mutations/actions and evaluates due reminders locally without pointless polling. Reminder evaluation runs only inside the visible authenticated app; no browser/system push notifications are used. Full UI semantics: `docs/ui/reminders.md`.
- Note mutations: `/api2/notes/*` → `app/usecases/Cmd*` → sqlite helpers → update NoteStore + bump sync UUID.
- Undo/Redo: `/api2/notes/undo|redo` → `app/usecases/undo.py` / `app/usecases/redo.py` → `app/services/undo_state.py`.
- Undo scope contract: ordinary undo tracks supported local saved actions, not arbitrary bulk operations. Existing global actions invalidate history. Bulk AI proposal generation/acceptance/rejection clears existing undo **and** redo only after successful application, creates no undo entry, and offers no bulk Undo. Failure/cancellation/decline/no changes preserve history; individual proposal controls remain undoable. Atomic application does not mean undoability. See `docs/ui/state-handling.md`. Opening the command palette no longer advances the epoch; successful bulk operations own the boundary.
- Auth status: `GET /api2/auth/status` is polled by the client to detect session/auth changes.
- Startup: explicit single-namespace `main.py` runs can select a namespaced DB (`METALIST_NAMESPACE` or `--namespace`) before importing `app.main`; `app/main.py` then initializes schema + settings and freezes its process-local frontend snapshot for that selected DB. If encryption is disabled, it populates the content cache and hydrates NoteStore before enabling the read guard. If encryption is enabled, hydration is deferred until login (`POST /api2/auth/hydrate`) and the UI shows a first-load progress state. The hydration hot path decrypts, sanitizes, and extracts plain text once per note, publishes the completed cache in bulk, and reuses that text for NoteStore/search construction. Search eagerly builds tag postings only; quoted-text queries scan tag-filtered in-memory strings and cache their results instead of rebuilding millions of trigram postings during every hydration. Plain source-checkout `python main.py` uses the namespace switcher to restart/start every known namespace instead of running just `default` in-process.
- Legacy import: `convert-from-legacy.py` is a destructive fresh-import path that prompts for namespace/ports when omitted, deletes both the target notes DB and files sidecar, persists the launch profile after database recreation, stamps successful conversions at `CURRENT_DATABASE_VERSION`, validates generated ontology rules with the current parser while reporting/skipping invalid legacy rules, can prompt for password setup, and writes the same Argon2id vault metadata as runtime auth.

## Phase-one integrity and privacy safeguards
- `app/db/live_recovery.py`: durable checksummed rollback images for password creation/removal and archive/legacy restore; pair notes + files, commit marker after flush, startup recovery before audit/migrations. Hidden `.recovery` directories are live transaction state, never historical backups; preserve pending journals for retry.

## Runtime Storage Contract
- Note projections and ordinary authentication checks are memory-first after startup/hydration. Auth status/version/settings inspection, attachment retrieval and topology validation within mutations intentionally access SQLite.
- Startup or post-login hydration loads required namespace data from SQLite, decrypts it if needed, and populates service-owned in-memory stores/caches.
- Note rendering and view calculations use in-memory stores/caches; this does not imply the complete HTTP middleware/request lifecycle performs zero SQLite reads. F13 removes ordinary auth connections and repeated schema inspection; rendering/hash work still contributes to view latency.
- Mutations update in-memory state and write encrypted-at-rest rows to SQLite. SQLite is effectively write-only after startup for normal runtime behavior.
- New persisted namespace features should follow the same pattern: schema + load-all bootstrap + service cache + write-through encrypted persistence; do not add runtime DB lookup paths.
